## Defect

The blend backtest harness (`scripts/backtest_blend_harness.py`) writes
durable state to the LIVE forward-test state paths, not an isolated
sandbox. When invoked outside the service user (specifically as root,
which has write privileges to anything), the harness:

1. **Unconditionally deletes** `data/risk_state_blend.json` (line 271 of
   pre-fix harness: `state_path = PROJECT_ROOT / "data" / "risk_state_blend.json";
   if state_path.exists(): state_path.unlink()`).
2. **Triggers `KillSwitchManager` activations** through the FTMO guard
   wired at `forward_test_engine.py:535` (`self._kill_switch =
   KillSwitchManager()`), with state_dir defaulting to
   `data/kill_switches/`. When FTMOGuard engages FREEZE/KILL on a
   losing eval (production safety-critical, not a bug), the kill switch
   writes to `data/kill_switches/global.state`.

Combined with root ownership, these writes leave live engine state files
in a poisoned state. Two distinct contamination channels:

| Live file | Channel | Symptom |
|---|---|---|
| `data/risk_state_blend.json` | Direct `unlink()` | Live engine restart reads missing/empty state, sizer cannot reconcile open_risk |
| `data/kill_switches/global.state` | `KillSwitchManager.activate_global_kill` from FTMO guard | Live engine startup loads ACTIVE global kill from fake backtest trigger → trading frozen on fabricated evidence |

## Root cause

Three compounding defects:

1. **Hardcoded live path** for risk state deletion. The harness treats
   `data/risk_state_blend.json` as a writable cache without recognizing
   it as durable engine state. (Pre-fix harness:271-274.)

2. **Default `state_dir` on `KillSwitchManager()`** is `"data/kill_switches"`
   (`kill_switch.py:21`). The engine wires its own `_kill_switch` at
   `forward_test_engine.py:535` and never exposes a parameter for the
   harness to override. Result: any consumer that triggers a kill writes
   to live state.

3. **No startup guard.** The harness will run regardless of:
   - `data/forward_test.pid` presence (indicates live engine active)
   - Ownership mismatch on live state files (indicates prior harness
     contamination, or a foreign user attempting to run)

## Fix design

Stay within allowed_files: `scripts/backtest_blend_harness.py` +
`tests/unit/scripts/test_backtest_blend_harness_isolation.py`. No
changes to `kill_switch.py` (its `state_dir` parameter already exists
since the original architecture — just never threaded from the harness).

1. **Parameterize state paths.** Add `--state-dir PATH` CLI arg
   (default: a fresh `tempfile.mkdtemp(prefix="ayumi_harness_state_")`
   per-run). All harness writes (risk state, kill switch state,
   intermediate test balance) flow through this directory.

2. **Rewire `engine._kill_switch` before `_build_components()`.** The
   engine's `__init__` constructs its own default `KillSwitchManager()`
   (which loads + may write to `data/kill_switches/`). The harness
   constructs an isolated instance with `state_dir=isolated_dir/"kill_switches"`,
   `disabled=False`, then assigns `engine._kill_switch = isolated_ks`
   **before** `engine._build_components()`. Every consumer wired at
   `forward_test_engine.py:989/992/1029/1041/1100/1103` (market_feed,
   ExecutionPermissionPolicy, PositionMonitor, PaperTrader._risk_guard)
   receives the isolated instance via `self._kill_switch`.

3. **Startup guard.** New `_verify_isolation_or_refuse()` runs at the
   top of `run_backtest()`. Refuses on:
   - `data/forward_test.pid` exists with live PID responding to `kill -0`
   - Any of `data/kill_switches/global.state`, `data/risk_state_blend.json`
     owned by a different user than the invoking user
   - Bypass: `--allow-foreign-ownership` (operator-only, logged)

4. **Move the risk-state deletion** from `data/risk_state_blend.json` to
   `isolated_dir/risk_state_blend.json`. No more unconditional live writes.

5. **Tests** (`tests/unit/scripts/test_backtest_blend_harness_isolation.py`):
   - `test_isolation_guard_refuses_when_pid_file_present`
   - `test_isolation_guard_refuses_on_foreign_ownership`
   - `test_isolation_guard_allows_with_allow_foreign_ownership_flag`
   - `test_isolation_guard_passes_clean_state`
   - `test_default_state_dir_is_isolated_temp_dir`
   - `test_isolated_killswitch_writes_only_to_isolated_dir_not_live`
   - `test_live_risk_state_path_unmodified` (integration-ish: simulate
     full `run_backtest` path and assert live sentinel files unchanged)
